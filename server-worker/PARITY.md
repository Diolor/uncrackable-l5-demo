# Verifier parity with the Kotlin oracle

The TypeScript verifier in `src/verifier/` is a port of the Kotlin server's `AndroidVerifier`
and the parts of Google's `android-key-attestation` verifier (`third_party/`) that decide the
verdict. The Kotlin server remains the reference; it is never deleted while this port is in
production. Every change to `src/verifier/` must keep `npm run parity` green.

## How parity is checked

`test/parity/run.ts` builds one JSON-lines file of cases and feeds it to both implementations:

1. **Synthetic corpus** from Google's own test certificate factory, generated by
   `ParityCorpus.kt` (73 cases: chain shapes, key-description variations, revocation, clocks).
2. **The recorded OnePlus 9 Pro chain** at its capture-time clock, plus bit flips and
   truncations at every byte of the leaf and at strides through the other three certificates.
3. **Structural mutations** built in TypeScript (`test/parity/cases.ts`): re-signed leaves with
   malformed or unusual KeyDescription encodings, tag classes, duplicate tags, RootOfTrust and
   AttestationApplicationId variants, certificate and chain shapes, distinguished-name
   canonicalisation, proof-of-possession encodings, revocation serial forms and clock edges.

The oracle (`ParityOracle.kt`, test classpath only) runs the production `AndroidVerifier` and
prints one verdict per case. Verdicts must be identical: `ok:2`, or one of the protocol codes
`attestation_invalid`, `app_integrity`, `device_integrity`, `no_hardware_attestation`.

Run:

```bash
cd server-worker && npm run parity          # full: about 3,000 cases
node --experimental-strip-types test/parity/run.ts --quick
```

The corpus is regenerated with
`PARITY_OUT=$PWD/server-worker/test/parity/out/corpus.jsonl ./gradlew :server:runLocal -PlocalMain=org.owasp.uncrackable.server.ParityCorpusKt`.

## Semantics that were not obvious and are pinned by cases

- **Two error classes in the extension parser.** Upstream `ExtensionParsingException` inside an
  attribute conversion nulls that attribute and continues; a later constraint then names it
  (for example a malformed `attestationApplicationId` yields `app_integrity`). `require`/`check`
  failures and BouncyCastle parse errors abort the whole parse (`attestation_invalid`).
- **Explicit tagging only.** A primitive context tag, or a constructed one with zero or two
  children, is a fatal parse error. Application- and private-class tags are accepted as tagged
  objects. Duplicate tags: last wins.
- **`hasAttestationExtension` consults non-critical extensions only.** A critical attestation
  extension on the leaf makes the target "missing" its extension; a critical one on an
  intermediate is not detected.
- **Distinguished names** compare like `X500Principal.equals`: only RFC 2253 keyword attributes
  (CN, O, OU, C, L, ST, STREET, DC, UID) in PrintableString or UTF8String are case- and
  whitespace-normalised. Everything else, including `serialNumber` and `title`, compares by exact
  DER bytes, so `SERIALNUMBER=DECAFBAD` and `serialNumber=decafbad` are different issuers.
- **Signature algorithm identifiers** in the TBS and the outer certificate must agree.
- **Trust anchor selection** tries every configured anchor whose subject equals the issuer of the
  certificate below the root; the chain's own root certificate is never signature-checked, only
  its self-issuance and serial (revocation) matter.
- **Validity**: intermediate expiry is ignored on factory-provisioned chains, enforced on remotely
  provisioned and unknown chains; `notBefore` is always enforced; the leaf's own validity is
  enforced by the server layer, not by Google's validator.
- **Serials** are unpadded lowercase hex (`BigInteger.toString(16)`), negative values keep a sign.
- **Base64** follows `java.util.Base64`: no whitespace, optional but correct padding, standard
  alphabet for chain and proof, URL alphabet for the challenge.

## Documented divergences

| Case | Kotlin | TypeScript | Why |
| --- | --- | --- | --- |
| `kd-indefinite-length-ber` (BER indefinite length inside the attestation extension) | accepts | rejects | BouncyCastle tolerates BER; the port is DER-strict. KeyMint emits DER, so no genuine device is affected, and the divergence only ever rejects. |

Known but unexercised: a leaf key whose SubjectPublicKeyInfo carries explicit EC parameters equal
to P-256 is accepted by Java and rejected by WebCrypto import. No Android KeyMint emits explicit
parameters. Both divergences are reject-only.
